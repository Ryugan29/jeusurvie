# Décisions techniques de la migration

| # | Décision | Pourquoi | Alternative écartée |
|---|---|---|---|
| D1 | **Unity 6.6 (6000.6.7f1), URP** | Pipeline de référence d'Unity 6, 4 profils LOW→ULTRA portables sur « PC moyen », Render Graph, SSAO, ombres en cascade, Volume. | HDRP : plus riche (SSR, nuages volumétriques natifs) mais lourd, hors de la cible « PC moyen » et des profils LOW/MEDIUM. |
| D2 | **Cœur pur `JeuSurvie.Core`** (asmdef `noEngineReferences`) = port ligne à ligne de `src/core`, `src/app` et `src/adapters/render-data` | Reprend l'architecture validée (ADR 0001) : règles testables hors moteur ; permet de **prouver la parité** contre le TypeScript sans Unity. | Réécrire la logique dans des MonoBehaviours : intestable ici, perte des garanties. |
| D3 | **Déterminisme bit à bit** du générateur (mêmes graines ⇒ mêmes mondes que la version navigateur) | ADR 0004 (genVersion 1 scellé) : les valeurs d'or doivent rester vraies. Doubles IEEE, `Math.imul` → multiplication `int` non vérifiée, `Math.fround` → `(float)`, `Math.round` JS réimplémenté (C# arrondit au pair). | Bruits de Unity (Mathf.PerlinNoise) : autre monde. |
| D4 | Tests NUnit **communs** à Unity (Test Runner, EditMode) et à `dotnet test` (Tools~/CoreTests) ; fixtures générées en exécutant le TS d'origine (Tools~/parity) | Preuve reproductible de la parité ; tourne en CI sans licence Unity. | |
| D5 | **Génération des chunks sur threads** (`ChunkWorkerSource`) | Équivalent direct des Web Workers ; le code généré est pur et sans état partagé. | Jobs/Burst : demanderait de réécrire le générateur en types blittables (risque de parité). |
| D6 | **glTFast au runtime** depuis `StreamingAssets/assets/models` | Les modèles CC0 sont chargés par chemin, exactement comme `/assets/models/` dans le navigateur ; aucun réglage d'importeur à maintenir ; dégradation identique (modèle illisible ⇒ le jeu continue sans). | Import éditeur en prefabs : dépend des réglages d'import et casse si les assets manquent. |
| D7 | **GPU instancing** (`Graphics.RenderMeshInstanced`) pour végétation et couvre-sol, matrices au format Babylon réinterprétées telles quelles | Équivalent des thin instances (un tracé par morceau de modèle) ; la disposition mémoire des matrices Babylon est celle d'Unity. | GameObjects par arbre : des dizaines de milliers d'objets. |
| D8 | **Ombres proches** = second tracé `ShadowsOnly` des seules instances à portée | Forme native des « shadow proxies ». | Toutes les instances projetant : coût prohibitif dans chaque cascade. |
| D9 | **Ciel en skybox URP** (shader porté ligne à ligne) | Dessiné après l'opaque à profondeur lointaine (= « ciel » pour la perspective et les rayons), capturé automatiquement par la sonde de réflexion (IBL du ciel de l'heure). | Sphère suivant la caméra : profondeur et sonde à gérer à la main. |
| D10 | **Un seul asset URP réglé à chaud** par le profil (setters publics + réflexion gardée pour la résolution d'ombre et la qualité d'ombre douce) | Le jeu d'origine applique le profil sans recharger ; la réflexion est encapsulée, sans effet si un champ change de nom (avertissement unique). | 4 assets + niveaux de qualité : il faut éditer QualitySettings.asset à la main. |
| D11 | **Passes plein écran maison** (Render Graph) : perspective atmosphérique, flou de distance, rayons, reflets du mouillé, netteté + gouttes | URP n'a ni perspective atmosphérique, ni SSR, ni gouttes ; les shaders Babylon sont portés tels quels. | Brume URP seule : perd la brume de hauteur intégrée et la diffusion de Mie. |
| D12 | Post-traitement par **Volume URP créé au runtime** (Bloom, ACES, ColorAdjustments, Vignette, FilmGrain, MotionBlur) | Natif, piloté chaque image par l'étalonnage de l'heure (`GradeFor` + météo). | |
| D13 | **Input System** (touches par position physique : ZQSD en AZERTY comme `KeyboardEvent.code`), repli Input Manager via `#if` | Natif Unity 6 ; le code compile dans les deux modes de gestion des entrées. | |
| D14 | **UI Toolkit** construit en code + USS (port du CSS) | Équivalent direct du DOM sans framework (ADR 0008) ; texte en texte brut seulement. | uGUI : plus lourd, éloigné du CSS d'origine. |
| D15 | Préférences graphiques dans **PlayerPrefs**, même clé (`jeusurvie.graphismes.v1`) et même JSON | Parité de format ; lecture tolérante (ADR 0005/0006). | |
| D16 | Paramètres d'adresse → **arguments de ligne de commande** de mêmes noms (+ champ `launchArguments` dans l'inspecteur) | Conserve tous les interrupteurs de démo et de mesure. | |
| D17 | **Configuration automatique du projet** à la première ouverture (`Editor/ProjectSetup.cs`) | Les assets URP / renderer / features ne peuvent pas être écrits à la main de façon fiable (GUID de scripts de paquets) ; l'éditeur les crée lui-même. Relançable : menu *Jeu Survie → Configurer le projet*. | YAML écrit à la main : fragile. |
| D18 | Le bootstrap se crée seul au Play (`RuntimeInitializeOnLoadMethod`) | Le jeu démarre même depuis une scène vide. | |
| D19 | Couleurs envoyées aux shaders en **vecteurs linéaires** (`SetVector`), couleurs Unity (lumière, ambiance, brume) via `.gamma` | Unity convertit sRGB→linéaire dans `SetColor`/`Light.color` ; les valeurs Babylon sont déjà linéaires. | |
| D20 | Écarts assumés (adaptations natives) : PCSS → ombres douces High ; SSR maison limité au sol plat mouillé ; rayons occultés par la profondeur caméra (l'herbe proche occulte aussi) ; grain avant la netteté | Pas d'équivalent exact dans URP ; effets visuellement proches. À juger à l'œil (MIGRATION_BLOCKERS.md). | |
